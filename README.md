# رفیق‌سنج | KnowMe Android

یک MVP فارسی و راست‌به‌چپ با Flutter: آزمون پنج‌سؤالی درباره صاحب آزمون، پاسخ‌گویی، امتیاز و اشتراک‌گذاری نتیجه.

## وضعیت فعلی
- [x] رابط کاربری فارسی و RTL
- [x] انتخاب نام مستعار
- [x] انتخاب جواب صحیح برای ۵ سؤال
- [x] اجرای آزمون و محاسبه امتیاز
- [x] اشتراک‌گذاری نتیجه با share sheet اندروید
- [ ] لینک آنلاین اختصاصی و پاسخ‌گویی در مرورگر
- [ ] ذخیره‌سازی Firebase و لینک دعوت
- [ ] تست روی دستگاه واقعی و انتشار عمومی

## اجرا در Android Studio
1. Flutter SDK و Android Studio را نصب کن.
2. این مخزن را clone کن.
3. در ریشه پروژه اجرا کن: `flutter create --platforms=android --org com.mrbzr66 .`
4. سپس اجرا کن: `flutter pub get` و `flutter run`

شناسه برنامه باید `com.mrbzr66.knowme` بماند.

## ساخت APK
```bash
flutter build apk --release
```

## سیاست حیاتی برای آپدیت بدون حذف نسخه قبلی
برای اینکه نسخه جدید روی نسخه قبلی نصب شود:
1. **Application ID** را ثابت نگه دار: `com.mrbzr66.knowme`.
2. **همان کلید امضای release** و alias نسخه اول را نگه دار و امن پشتیبان بگیر.
3. عدد بعد از `+` در `pubspec.yaml` را در هر انتشار افزایش بده؛ مثلاً `1.0.0+1` سپس `1.0.1+2`.
4. APK هر نسخه باید با همان کلید امضا شود. اگر keystore گم شود یا عوض شود، نصب به‌عنوان آپدیت معمولی ممکن نیست.

### امضای پایدار در GitHub Actions
در مخزن GitHub از مسیر Settings → Secrets and variables → Actions این secrets را تنظیم کن:
- `ANDROID_KEYSTORE_BASE64`: محتوای Base64 فایل keystore ثابت
- `ANDROID_KEY_ALIAS`: alias کلید
- `ANDROID_KEY_PASSWORD`: رمز کلید
- `ANDROID_STORE_PASSWORD`: رمز keystore

یک keystore را فقط یک‌بار روی سیستم خودت بساز و فایل و رمزهایش را هرگز در Git commit نکن. تا قبل از تنظیم secrets، workflow فقط APK آزمایشی debug می‌سازد؛ امضای debug در runnerهای جدا تضمین‌شده ثابت نیست، پس این فایل‌ها برای آزمون رابط‌اند نه آپدیت release.
